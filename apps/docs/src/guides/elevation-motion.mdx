# Elevation & Motion

Both of these are about the same thing: telling a user what is happening in
space and time without saying it in words. The surfaces below cast their
real shadows, and the demos below animate at their real durations and
easings - hover them.

## Elevation

Elevation answers "what is on top of what". Six levels, and the number is a
**meaning**, not a taste: the higher a surface, the more it interrupts.

export const levels = [
  ['0', 'Flat page content. Use a border for separation, not a shadow.'],
  ['1', 'Resting cards and raised surfaces within the page.'],
  ['2', 'Hovered card, sticky header once the page has scrolled.'],
  ['3', 'Menus, dropdowns, popovers - transient, anchored to a trigger.'],
  ['4', 'Dialogs and drawers - modal, interrupting the page.'],
  ['5', 'Rare. Reserved for something that must sit above a dialog.'],
];

In **dark mode**, shadows read weakly against a dark background - that is a
physical fact, not a bug to work around by darkening them further. Lean on
the surface-container ramp (`--color-surface-container`,
`-container-high`, ...) to carry the hierarchy instead: a lighter surface
reads as nearer. Switch **Theme** in the toolbar above and watch the cards
above lose most of their separation, then compare with the ramp below.

## Motion

Motion explains a change - where a thing came from, or that the system
heard you. Motion that does neither is decoration, and decoration on a tool
someone uses for eight hours a day becomes friction.

### Durations

Hover each swatch to see it move at that duration.

## Reduced motion

Some people get genuinely ill from movement on screen - vestibular
disorders make large transforms and parallax nauseating, not merely
annoying. `prefers-reduced-motion` is an accessibility requirement (WCAG
2.3.3), not a preference to respect when convenient.

Honour it globally, once:

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: var(--motion-duration-instant) !important;
    animation-iteration-count: 1 !important;
    transition-duration: var(--motion-duration-instant) !important;
    scroll-behavior: auto !important;
  }
}
```

Reduced does not mean removed. A cross-fade conveys the same "this
changed" without moving anything through space, and is usually the right
substitute for a slide.

## Do

- Animate `transform` and `opacity`. They are the only two properties the
  browser can animate off the main thread; animating `width`, `top` or
  `box-shadow` forces layout on every frame and janks.
- Match the duration to the distance travelled. A 4px hover shift at 300ms
  feels broken; a full-screen drawer at 100ms feels like a glitch.
- Use `decelerate` for entrances and `accelerate` for exits, so things
  appear to arrive from and depart to somewhere real.

## Don't

- Don't animate anything that blocks input. If a user can outrun the
  animation, the animation is too slow.
- Don't stack shadows to build hierarchy in dark mode - use the surface
  ramp.
- Don't put motion on something that changes constantly. A value that
  animates on every keystroke is noise.

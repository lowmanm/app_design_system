# Iconography

The system's icon set is **Material Symbols Outlined**, self-hosted and
wrapped in `<brk-icon>`. Every glyph on this page is the real font
rendering at the real token sizes.

```html
<brk-icon name="settings" />
<brk-icon name="check_circle" size="lg" filled />
<brk-icon name="delete" label="Delete this row" />
```

Outside Angular, the same thing is a span - the stylesheet does all the
work, so Tailwind, Bootstrap and plain-HTML apps get identical icons
without a per-framework sprite loader:

```html
<span class="brk-icon brk-icon--lg">settings</span>
```

## Accessibility: the one rule that matters

**Icons are decorative by default.** `<brk-icon>` sets `aria-hidden` unless
you give it a `label`, and that default is deliberate: most icons sit right
next to their own text, and announcing them makes a screen reader say
"delete delete".

Pass `label` **only** when the icon is the sole thing naming a control -
typically an icon-only button. That turns it into `role="img"` with an
accessible name.

Icons also **inherit colour** rather than setting it, so an icon inside a
danger menu item turns red with the item and needs no styling of its own.

## Sizes

Four steps, from the `--icon-size-*` tokens. The font's optical-size axis
is driven from the same value, so strokes stay optically correct instead of
thinning out as an icon grows.

export const iconSizes = [
  ['sm', '20px', 'Inline with body text, inside dense controls.'],
  ['md', '24px', 'The default. Buttons, menu items, form fields.'],
  ['lg', '32px', 'Section headers, list leading icons.'],
  ['xl', '40px', 'Empty states and feature blocks.'],
];

<div style={{ display: 'grid', gap: 'var(--space-3)' }}>

## Fill and weight

Material Symbols is a variable font. `filled` is the one axis that carries
**meaning** - conventionally, a filled icon is the selected or active state
of an outlined one, which is why nav bars fill the current item's icon.
`weight` and `grade` are optical adjustments for matching heavier text or
holding up on dark backgrounds.

## How it works, and what it costs

An icon is **text**. `name="settings"` puts the literal word in the
element, and the font's ligature table substitutes the glyph. That is what
makes one markup pattern work in every framework - and it is why
`translate="no"` is set on the host, since a page translator that rewrites
the word renders tofu instead of an icon.

**The font is ~3.8 MB**, carrying all glyphs across all four axes. This is
a known, deliberate trade-off:

- `font-display: block` shows a brief blank rather than flashing the word
  "settings", and the file is immutable so it caches indefinitely - a
  once-per-user cost.
- **Per-app subsetting does not work with a ligature font.** Subsetters
  keep the glyphs reachable from the text you give them; every icon name is
  made of ordinary letters, so the closure over `a`–`z` reaches every
  ligature and keeps everything. Measured on a 94-icon list, the "subset"
  came out 8% smaller. Cutting it for real means subsetting by private-use
  codepoints and writing `&#xe8b8;` instead of `name="settings"` - giving
  up the readable API. If an app's budget ever makes that trade worth it,
  it is a per-app decision, not a system default.

## Do

- Pair an icon with a text label wherever space allows. Icon-only controls
  are learnable, not self-evident, and they fail hardest for the people who
  use a product least often.
- Use one icon per concept across the whole product - the curated set above
  exists to make that the path of least resistance.
- Use `filled` to mean selected/active, and leave outlined as the resting
  state. Users already read that convention from every OS they use.

## Don't

- Don't label a decorative icon. A screen reader announcing "delete delete"
  is worse than one that says nothing.
- Don't set an icon's colour directly. Colour it by colouring the text
  around it, so states like `danger` and `disabled` work for free.
- Don't paste inline SVG for something the set already has - that is how a
  codebase ends up with four visually different trash cans.
- Don't use an icon to carry information that appears nowhere else. Icons
  are recognition aids, not content.
